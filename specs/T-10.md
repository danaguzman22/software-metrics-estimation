# T-10 — CI con PostgreSQL

- **Issue:** #47
- **Tipo:** técnica / infraestructura de CI
- **Story points:** 2 SP
- **Estado:** Implementada localmente; pendiente validar el run de GitHub Actions
- **Rama:** `feature/T-10-ci-postgresql` → PR a `migracion/postgresql`
- **Decisiones del ADR-001:** D9 (`TEST_DATABASE_URL`); sección 6, paso 8
- **Depende de:** T-13 (#46)

## 1. Contexto

T-13 agrega la suite de contrato y las pruebas de integración de los
repositorios PostgreSQL. Este cambio configura GitHub Actions para ejecutar la
suite contra PostgreSQL en CI, sin alterar el comportamiento local: cuando
`TEST_DATABASE_URL` no está definida, los tests de integración se omiten.

Esta tarea es de infraestructura, sin comportamiento de usuario; no genera
`.feature`. Es el único issue autorizado a modificar
`.github/workflows/ci.yml`. Dockerfile y Docker Compose quedan fuera de alcance.

## 2. Alcance

**Incluye:** servicio PostgreSQL 13 o superior con health check, configuración
de `TEST_DATABASE_URL` para el job de tests y ejecución de la suite completa en
pushes y pull requests dirigidos a `migracion/postgresql`.

**No incluye:** cambios en tests o código de los repositorios, Docker/Compose,
otros workflows ni modificaciones a workflows fuera de T-10.

## 3. Reglas

- **R1 — Servicio PostgreSQL:** el job de CI declara un servicio PostgreSQL
  13+, con credenciales y health check para esperar a que acepte conexiones.
- **R2 — URL de pruebas:** el job de tests exporta `TEST_DATABASE_URL`, usando
  el hostname/puerto del servicio de Actions y `sslmode=disable`.
- **R3 — Suite completa:** el paso existente `go test ./... -cover` corre con
  `TEST_DATABASE_URL` presente, por lo que incluye `TestPostgresRepo_Contrato`
  y los tests de integración T-13, no solo tests locales que omiten la base.
- **R4 — Disparadores:** el workflow corre en push como hoy y en pull requests
  dirigidos a `migracion/postgresql`, además de los destinos existentes.
- **R5 — Compatibilidad local y frontera:** los tests siguen omitiendo la
  integración al no tener `TEST_DATABASE_URL`; el único workflow modificado es
  `.github/workflows/ci.yml`.

## 4. Criterios de aceptación

- **CA1:** `.github/workflows/ci.yml` declara un servicio PostgreSQL 13+ con
  health check.
- **CA2:** `TEST_DATABASE_URL` está disponible para el paso de tests.
- **CA3:** los tests de contrato e integración PostgreSQL corren en Actions.
- **CA4:** los tests de integración se omiten al ejecutar localmente sin
  `TEST_DATABASE_URL`.
- **CA5:** CI valida pushes y PRs dirigidos a `migracion/postgresql`; build y
  suite completa pasan.
- **CA6:** no se modifica ningún otro workflow ni configuración Docker/Compose.

## 5. Trazabilidad CA → verificación

| CA | Verificación |
|---|---|
| CA1 | Revisión del servicio PostgreSQL y health check en el workflow; ejecución satisfactoria del job |
| CA2 | Revisión de `TEST_DATABASE_URL` en el entorno del job y salida de los tests de integración |
| CA3 | Run de GitHub Actions con `TestPostgresRepo_Contrato` y tests PostgreSQL ejecutados sin SKIP por variable ausente |
| CA4 | `go test ./... -count=1` sin la variable; tests PostgreSQL informan SKIP y el resto pasa |
| CA5 | `docs/evidencias/T-10-green.txt` valida localmente build y suite con PostgreSQL 16; falta confirmar un run verde de GitHub Actions al publicar la rama/PR |
| CA6 | `git diff --name-only` confirma cambios limitados al workflow, spec y evidencias propios de T-10 |

## 6. Trazabilidad

ADR-001, decisión D9 (`TEST_DATABASE_URL`), sección 6, paso 8 y frontera de
issues de la sección 11. Suite PostgreSQL: T-13 (#46), implementada en
`internal/storage/postgres`.

Evidencias: `docs/evidencias/T-10-red.txt` registra la línea base sin
`TEST_DATABASE_URL`, que omite los tests PostgreSQL; `docs/evidencias/T-10-green.txt`
registra build y suite completa contra PostgreSQL 16. En GREEN, el subtest
`TestT08_ErroresInfraestructura_EnvuelvenConW` se omite porque el adaptador
PostgreSQL no implementa `InyectarFallo`, limitación ya documentada en T-13;
los demás tests de contrato e integración se ejecutan.

El run de GitHub Actions aún debe confirmarse al publicar la rama/PR.
