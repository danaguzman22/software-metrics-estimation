## Fuente única de requisitos

> Como integrante, quiero crear un proyecto con nombre, fecha de inicio y fecha de fin, para empezar a gestionarlo.
>
> Prioridad: Alta. Story Points: 3. Sprint: S1.
>
> Criterios de aceptación:
> - Se crea con nombre, fecha de inicio y fecha de fin.
> - Nombre vacío devuelve error de validación.
> - Fecha de fin anterior a la de inicio devuelve error.
> - El proyecto queda con estado inicial `Planificado`.

Esta spec no agrega requisitos fuera de esa fuente. Todo lo ambiguo se lista en **Decisiones pendientes de confirmación**.

## 1. Objetivo

Permitir que un integrante cree un proyecto indicando nombre, fecha de inicio y fecha de fin, para poder empezar a gestionarlo.

El alcance de esta historia es la creación del proyecto con esos tres datos y su estado inicial. No incluye edición, listado, borrado, transiciones de estado, interfaz, persistencia ni permisos, porque la historia no los menciona.

## 2. Datos del proyecto

Solo se consideran los datos que la historia menciona.

| Dato | Descripción | Origen del requisito |
|---|---|---|
| Nombre | Identifica al proyecto. No puede estar vacío. | Historia y CA2 |
| Fecha de inicio | Fecha desde la cual comienza el proyecto. | Historia y CA1 |
| Fecha de fin | Fecha en la que finaliza el proyecto. No puede ser anterior a la fecha de inicio. | Historia y CA3 |
| Estado | Estado del proyecto. Al crearse queda en `Planificado`. | CA4 |

No se definen otros campos, identificadores, formatos de fecha, zona horaria ni reglas de unicidad del nombre.

## 3. Reglas de negocio

Cada regla es verificable mediante un test.

| ID | Regla | Verificación esperada | CA |
|---|---|---|---|
| R1 | Un proyecto se crea con los tres datos: nombre, fecha de inicio y fecha de fin. El proyecto resultante conserva los valores recibidos. | Test que crea un proyecto con datos válidos y comprueba que el nombre, la fecha de inicio y la fecha de fin coinciden con los ingresados. | CA1 |
| R2 | El nombre no puede estar vacío. Si el nombre está vacío, la creación devuelve un error de validación y no se completa exitosamente. | Test que intenta crear un proyecto con nombre vacío y verifica que se devuelve un error de validación. | CA2 |
| R3 | La fecha de fin no puede ser anterior a la fecha de inicio. Si la fecha de fin es anterior a la fecha de inicio, la creación devuelve un error y no se completa exitosamente. | Test que intenta crear un proyecto con fecha de fin anterior a la fecha de inicio y verifica que se devuelve un error. | CA3 |
| R4 | Todo proyecto creado válidamente queda con estado inicial `Planificado`. | Test que crea un proyecto con datos válidos y verifica que su estado es exactamente `Planificado`. | CA4 |

Notas de interpretación (a confirmar):

- **R3 / fechas iguales:** el texto solo define como error que la fecha de fin sea **anterior** a la de inicio. Que ambas fechas sean **iguales** no se define como error. Esta lectura queda marcada para confirmación (D1).
- **R2 / "vacío":** la historia no define si "vacío" incluye un nombre compuesto solo por espacios. Queda marcado para confirmación (D2).
- **R2 y R3 / proyecto no creado:** la historia dice que se devuelve error, pero no detalla efectos posteriores (por ejemplo, si algo se guarda). No se agrega ese comportamiento como requisito (D8).

## 4. Validaciones

Solo se documentan las validaciones que la historia pide.

| ID | Validación | Resultado esperado | Regla |
|---|---|---|---|
| V1 | Nombre vacío | Error de validación | R2 |
| V2 | Fecha de fin anterior a la fecha de inicio | Error | R3 |

No se agregan validaciones adicionales (por ejemplo, longitud del nombre, caracteres permitidos, fechas obligatorias, duplicados, formatos o rangos), porque la historia no las pide.

## 5. Comportamiento esperado

### Caso normal

1. El integrante ingresa nombre no vacío, fecha de inicio y fecha de fin con fecha de fin igual o posterior a la fecha de inicio.
2. El proyecto se crea con esos datos.
3. El proyecto queda con estado `Planificado`.

Resultado: creación exitosa (R1, R4).

### Casos alternativos / de error

- Si el nombre está vacío, la creación devuelve un error de validación (R2, V1).
- Si la fecha de fin es anterior a la fecha de inicio, la creación devuelve un error (R3, V2).

### Casos límite

- Fecha de fin igual a la fecha de inicio: según el texto no es error; **pendiente de confirmación** (D1).
- Nombre con solo espacios: no definido por la historia; **pendiente de confirmación** (D2).
- Fechas ausentes o incompletas: no definido por la historia; **pendiente de confirmación** (D4).
- Nombre y fechas inválidos a la vez: no se define qué error prevalece; **pendiente de confirmación** (D5).
