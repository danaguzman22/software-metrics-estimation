## 1. Objetivo

Permitir que un Product Owner consulte el estado de un proyecto para saber cuánto avanzó. La consulta muestra:

1. El estado del proyecto calculado por fechas: `Planificado`, `En curso` o `Finalizado` (D1).
2. El sprint actual, recibido como dato; vacío significa "sin sprint activo" (D3).
3. El porcentaje de historias completadas, calculado como función pura a partir del total de historias y de las historias completadas, redondeado a 2 decimales y con 0% cuando no hay historias (D3, D4).

La consulta es de solo lectura: no modifica el campo `Estado` guardado ni la regla de US-02 que lo conserva (D1). El estado calculado y el estado guardado pueden no coincidir.

El alcance de esta historia es la especificación del dominio de la consulta de forma independiente: cálculo de estado por fechas, porcentaje y representación del sprint actual. No incluye la integración real con Sprints e historias, la creación de tipos `Sprint` o `Historia`, la búsqueda del proyecto por ID, persistencia nueva, interfaz web ni permisos. La búsqueda del proyecto por ID está a cargo de Dana y aún no está integrada; se registra como dependencia abierta (D5, P5).

## 2. Alcance

### Incluido

- Cálculo del estado por fechas con una fecha "hoy" recibida por parámetro (D1).

- Sprint actual como dato recibido; vacío = "sin sprint activo" (D3).
- Porcentaje de historias completadas como función pura con total y completadas recibidos por parámetro (D3, D4).
- Comportamiento sin historias: 0% sin error ni división por cero (CA2, D4).
- Carácter de solo lectura de la consulta respecto del estado guardado (D1).

### Fuera de alcance

- Crear tipos `Sprint` o `Historia` (D3).
- Integrar realmente Sprints o backlog para obtener el sprint actual, el total y las completadas (D3, P4).
- Buscar el proyecto por ID o definir el contrato concreto de esa búsqueda (D5, P5).
- Crear otra solución de persistencia o de búsqueda paralela (D5).
- Modificar `internal/storage` o T-02.
- Modificar el campo `Estado` guardado o la regla de US-02 que lo conserva (D1).
- Interfaz web, `cmd/server`, permisos, autenticación o roles de usuario.
- Validaciones o reglas no pedidas por la issue ni por D1–D10.

Notas de interpretación (D1–D10):

- **Estado calculado vs estado guardado (D1):** el estado que muestra la consulta no es el campo `Estado` persistido. Se calcula por fechas con la fecha "hoy" recibida. El campo guardado no se modifica y la regla de US-02 que lo conserva sigue vigente. Por eso el estado calculado y el guardado pueden no coincidir.
- **Constantes de estado (D2):** se agregan `EstadoEnCurso` y `EstadoFinalizado` en `internal/domain`, junto a la existente `EstadoPlanificado`. No se agregan otros estados.
- **Sprint e historias (D3):** el sprint actual, el total de historias y las historias completadas se reciben por parámetro. No se crean tipos `Sprint` ni `Historia`. La integración real con Sprints y backlog queda como dependencia de esas historias (P4).
- **Porcentaje (D4):** es un valor de 0 a 100, redondeado a 2 decimales. Con 0 historias devuelve 0 sin error.
- **Búsqueda por ID (D5):** no se crea otra solución de persistencia ni de búsqueda paralela. La consulta de proyecto por ID está a cargo de Dana y todavía no está integrada (P5). El dominio se especifica de forma independiente.
- **Porcentaje y valores inválidos (D6):** la firma es `PorcentajeCompletadas(total, completadas int) (float64, error)`. El error nuevo propuesto en `internal/domain` se llama `ErrHistoriasInvalidas` y se devuelve si `total` o `completadas` son negativos, o si `completadas > total`.
- **Comparación por día (D7):** "hoy" se compara solo por día (año, mes y día), ignorando hora y zona horaria.
- **Proyecto inexistente (D8):** la consulta de servicio devuelve `domain.ErrProyectoNoEncontrado`. Su implementación depende de P5 y queda fuera de esta entrega.
- **Fechas inconsistentes (D9):** si `FechaFin` es anterior a `FechaInicio`, `EstadoPorFechas` devuelve `domain.ErrFechaFinAnteriorAInicio`. Las fechas cero no se validan, igual que en US-01 y US-02.
- **Firma del estado (D10):** `EstadoPorFechas(inicio, fin, hoy time.Time) (Estado, error)`.

## 7. Comportamiento esperado

### Caso normal

1. Se obtiene un proyecto existente con fecha de inicio, fecha de fin y su estado guardado (la obtención por ID está sujeta a P5).
2. Se recibe una fecha "hoy" comprendida entre la fecha de inicio y la fecha de fin, ambos extremos incluidos.
3. Se recibe el sprint actual (por ejemplo "Sprint 2"), el total de historias (por ejemplo 8) y las historias completadas (por ejemplo 5).
4. La consulta muestra el estado calculado `En curso` (R1).
5. La consulta muestra el sprint actual "Sprint 2" (R2).
6. La consulta muestra el porcentaje `62.5` (5 de 8, redondeado a 2 decimales, R3).
7. La consulta no modifica el estado guardado ni el proyecto persistido (R5).

Resultado: consulta exitosa con estado, sprint actual y porcentaje (CA1).

### Casos alternativos

- `hoy` anterior a la fecha de inicio: se muestra `Planificado` (R1).
- `hoy` posterior a la fecha de fin: se muestra `Finalizado` (R1).
- `hoy` igual a la fecha de inicio: se muestra `En curso` (extremo incluido, R1).
- `hoy` igual a la fecha de fin: se muestra `En curso` (extremo incluido, R1).
- Proyecto con fecha de inicio igual a la fecha de fin y `hoy` igual a esa fecha: se muestra `En curso` (R1).
- Sprint actual vacío: se muestra "sin sprint activo" (R2).
- Proyecto sin historias (total 0, completadas 0): se muestra 0% sin error (R4, CA2).
- Todas las historias completadas: se muestra 100% (R3).
- Ninguna historia completada con total mayor que cero: se muestra 0% (R3).
- `hoy` con hora distinta pero mismo día que la fecha de inicio: se muestra `En curso`, porque la comparación es solo por día (D7).
- Estado guardado distinto del calculado: se muestra el calculado por fechas y el guardado no se modifica (R1, R5).

### Casos límite y pendientes

- Porcentaje con redondeo a 2 decimales: 1 de 3 ⇒ 33.33; 2 de 3 ⇒ 66.67; 5 de 8 ⇒ 62.5 (R3).
- Total de historias 0: 0% sin error (R4, CA2).
- Total de historias 0 con completadas mayores que 0: devuelve error `ErrHistoriasInvalidas` porque `completadas > total` (D6).
- Completadas mayor que total o valores negativos: devuelve error `ErrHistoriasInvalidas` (D6).
- Comparación de "hoy" con hora o solo con el día: se compara solo por día (año, mes y día), ignorando hora y zona horaria (D7).
- Proyecto inexistente: la consulta de servicio devuelve `domain.ErrProyectoNoEncontrado` (D8); su implementación depende de P5 y queda fuera de esta entrega.
- Fechas cero o con `FechaFin` anterior a `FechaInicio`: si `FechaFin` es anterior a `FechaInicio`, devuelve `domain.ErrFechaFinAnteriorAInicio` (D9); las fechas cero no se validan (D9).
- Integración real con Sprints e historias: **PENDIENTE DE DECIDIR** (P4); esta spec solo define las entradas por parámetro.
- Búsqueda del proyecto por ID: **PENDIENTE DE DECIDIR** (P5).
