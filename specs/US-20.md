## 1. Objetivo y alcance

Entregar al Product Owner un **reporte imprimible** de un proyecto (`GET /proyectos/{id}/reporte`) y de un Sprint (`GET /proyectos/{id}/sprints/{numero}/reporte`), renderizado en el servidor como HTML y pensado para imprimirse como PDF desde el navegador, **sin librerías ni generación de PDF en el código** (CA1, CA2).

El alcance incluye:

- **FASE 1 — servicio:** un caso de uso nuevo `ServicioReportes` con `ReporteProyecto(proyectoID string) (ReporteProyecto, error)` y `ReporteSprint(proyectoID string, sprintNumero int) (ReporteSprint, error)` en `internal/service/reportes.go`, que **arma** los datos del reporte **reutilizando** los servicios existentes: `ServicioDashboard` (`ObtenerDashboard` — US-19), `ServicioSprints` (`ListarSprints`, `StoryPointsPlanificados`, `StoryPointsCompletados`, `VelocidadSprint`, `ListarItemsDelSprint` — US-08/US-09/US-16), `ServicioEsfuerzo` (`MetricasSprint`, `MetricasHistoria` — US-17; las horas del proyecto llegan vía dashboard), `ServicioBacklog` (`ListarBacklog` — US-06) y `ServicioDefectos` (`ListarDefectos` — US-15 para las listas; `MetricasDefectosPorProyecto`/`MetricasDefectosPorSprint` — US-18 — para los conteos globales de defectos: ver D6). **No se agregan métodos de repositorio ni migraciones.**
- **FASE 2 — capa web:** las dos páginas en `internal/web`, con botón **Imprimir** y estilos `@media print` (sin navegación, sin cortes de página en las tablas), enlazadas desde el detalle del proyecto y desde cada Sprint (D1). La web **solo renderiza**: no suma, no calcula, no redondea (D4).

Fuera de alcance (explícito):

- Generación de PDF en el servidor, librerías de impresión o cualquier dependencia nueva.
- Migraciones nuevas, cambios de esquema, métodos nuevos en los repositorios o cambios en `ServicioSprints`, `ServicioEsfuerzo`, `ServicioBacklog`, `ServicioDashboard`, `ServicioDefectos` y en `internal/domain` (R7, R10).
- JavaScript obligatorio para que el reporte funcione (excepción propuesta solo para el botón Imprimir, D10 DERIVADA).
- Exportación a archivo (CSV/Excel/PDF descargable).
- Gráficos SVG (el reporte es tabular; los gráficos los tiene el dashboard de US-19).
- Autenticación, roles de acceso, paginación, filtros o búsqueda dentro del reporte.
- Métricas nuevas o cambios en las existentes (US-16, US-17, US-18 y US-19 se consumen tal cual).
- Dependencia de US-18 (métricas de defectos) **acotada**: el reporte reutiliza `MetricasDefectosPorProyecto`/`MetricasDefectosPorSprint` (US-18, mergeada en `develop` vía PR #83) para los conteos globales de defectos; los conteos por severidad y por estado y las listas se arman a partir de `ListarDefectos` (US-18 no los expone). Ver D6.

## 3. Salidas esperadas

| Situación | Salida esperada |
|---|---|
| Página válida (proyecto) | HTML renderizado con `Content-Type: text/html; charset=utf-8`, navegación principal oculta en impresión, botón Imprimir visible en pantalla, encabezado con nombre y estado del proyecto, secciones de historias, métricas, horas, Sprints cerrados y defectos. HTTP 200. |
| Página válida (Sprint) | HTML renderizado igual, con Sprint Goal, fechas y estado del Sprint, historias asignadas, SP y horas, y defectos del Sprint. HTTP 200. |
| Sin datos | HTTP 200 con mensajes explícitos: "No hay historias", "No hay defectos", "Todavía no hay Sprints cerrados", etc., según la sección. Sin errores ni división por cero. |
| Proyecto inexistente | Página de error con el mensaje del dominio y HTTP 404 (D5). |
| Sprint inexistente | Página de error con el mensaje del dominio y HTTP 404 (D5). |
| Número de Sprint inválido en la ruta (no numérico o menor que 1) | Página de error con HTTP 404 (D5, V3). |
| Sprint cerrado sin snapshot de esfuerzo (anterior a US-17) | El reporte se muestra completo; el bloque de horas del Sprint informa "métricas no disponibles" y HTTP 200 (E3). |
| Error de infraestructura | Se registra el error en el log del servidor y se muestra un mensaje genérico con HTTP 500; el detalle no aparece en la respuesta (D5). |
| Ruta inexistente | HTTP 404. |
| Método HTTP no permitido en una ruta registrada | HTTP 405; el handler no se ejecuta. |

| ID | Decisión | Resolución |

| D1 | ¿Cómo se generan los reportes y dónde se enlazan? | **DECIDIDA:** dos páginas HTML imprimibles, sin PDF ni librerías: `GET /proyectos/{id}/reporte` (proyecto completo) y `GET /proyectos/{id}/sprints/{numero}/reporte` (un Sprint). Botón **Imprimir** y estilos `@media print` (sin navegación, tablas sin cortes). Enlazadas desde el detalle del proyecto y desde cada Sprint. |
| D2 | ¿Qué incluye el reporte del proyecto? | **DECIDIDA:** nombre y estado; historias planificadas y completadas con sus Story Points; totales de SP, velocidad promedio y porcentaje completado (reutilizando `ObtenerDashboard`); horas estimadas, reales y desviación; Sprints cerrados con velocidad; defectos por severidad y estado, con su lista. |
| D3 | ¿Qué incluye el reporte de un Sprint? | **DECIDIDA:** Sprint Goal, fechas y estado; historias asignadas con SP, estado y horas; SP planificados, completados y velocidad; horas estimadas vs reales; defectos detectados y resueltos en ese Sprint. |
| D4 | ¿Dónde se arman las cifras? | **DECIDIDA:** las arma un servicio nuevo, **DERIVADO** (por ejemplo `ServicioReportes` con `ReporteProyecto` y `ReporteSprint`) **reutilizando los servicios existentes**, sin repositorios nuevos ni migraciones; la web solo renderiza. |
| D5 | ¿Qué errores HTTP se usan y qué pasa sin datos? | **DECIDIDA:** proyecto o Sprint inexistente → 404; número de Sprint inválido → 404; infraestructura → 500 genérico con el detalle solo en el log. Sin datos: la página responde 200 con mensajes ("No hay historias", "No hay defectos"). |
| D6 | ¿El reporte depende de US-18 (métricas de defectos)? | **DECIDIDA (revisada en 2026-11-15 tras leer el servicio real):** el enunciado preveía armar los conteos por cuenta desde `ListarDefectos` si US-18 no estaba en `develop`. US-18 **sí está en `develop`** (PR #83) y sus métricas cubren parcialmente lo que el reporte necesita: `ServicioDefectos.MetricasDefectosPorProyecto(proyectoID) (domain.MetricasDefectos, error)` devuelve los **totales** detectados/resueltos del proyecto (`MetricasPorProyecto` en el adaptador: `count(*)` y `count(*) FILTER (estado = 'Resuelto' AND sprint_resolucion IS NOT NULL)`), y `ServicioDefectos.MetricasDefectosPorSprint(proyectoID, sprintNumero)` devuelve **detectados** (`count(*) FILTER (sprint_deteccion = numero)`) y **resueltos en el Sprint** (`count(*) FILTER (estado = 'Resuelto' AND sprint_resolucion = numero)`). **El reporte REUTILIZA esas dos métricas** para `Detectados`/`Resueltos` en el reporte de proyecto y en el de Sprint, en lugar de recontarlos desde `ListarDefectos`. **US-18 no expone conteos por severidad (Alta/Media/Baja) ni por estado (Abierto/En curso/Resuelto):** esos conteos, en cambio, **sí se arman localmente** en el servicio iterando `ListarDefectos`, porque no hay forma de obtenerlos de las métricas existentes sin agregar métodos a los repositorios (prohibido por D4/R10). La **lista** de defectos sigue saliendo de `ListarDefectos` (US-18 no devuelve filas). Consecuencia explícita: el reporte pasa a depender de US-18 para `Detectados`/`Resueltos`; un error de `MetricasDefectosPorProyecto`/`MetricasDefectosPorSprint` se propaga envuelto con `%w` → HTTP 500 genérico (V4, E2). |
| D7 | ¿En cuántas fases y PRs se entrega? | **DECIDIDA:** FASE 1 = servicio; FASE 2 = web. Si conviene, se propone un solo PR; la justificación está en D8 (DERIVADA). |

| D17 | ¿Cómo se lee el Sprint en el servicio sin agregar métodos de repositorio? | **DERIVADA:** `ServicioReportes` obtiene el Sprint con `s.sprints.ListarSprints(proyectoID)` y toma el de `Numero == sprintNumero`; si no aparece → `domain.ErrSprintNoEncontrado` **sin envolver** (V2). Alternativa descartada: enlace en la navegación principal (agranda el blast radius de los tests de US-22/US-19 sin aporte al CA). A confirmar. |

- La lógica de negocio vive en `internal/domain` y los servicios; `internal/web` no importa `internal/storage` ni `pgx` (R21).
- Las cifras las arma el servicio; la web no recalcula ni deriva nada ni contiene reglas de negocio (D4, R18, R23).
- Los contratos de repositorio siguen en `internal/service`; los adaptadores en `internal/storage/{jsonrepo,postgres}` (ADR-001).

- `internal/domain`, `ServicioSprints`, `ServicioEsfuerzo`, `ServicioBacklog`, `ServicioDashboard`, `ServicioDefectos` y los adaptadores **no se modifican** en ninguna fase (R10).

- Los textos visibles, mensajes de error y comentarios están en español; los archivos se guardan en UTF-8 sin BOM (AGENTS.md).

## 7. Casos límite

- **Proyecto sin historias ni Sprints ni defectos:** HTTP 200; todos los totales en cero; velocidad promedio `0.00`; porcentaje `0.00%`; horas `0.00 h` con desviación `—`; "No hay historias" en ambas listas; "No hay defectos"; "Todavía no hay Sprints cerrados" (D5, R15).
- **Proyecto con historias sin estimar en horas:** `EstimacionesCompletas = false`; horas estimadas suman solo las disponibles; la desviación se muestra como `—` con la nota de "historias sin estimar en horas" (D15, R18).
- **Proyecto con la suma de estimaciones en cero:** desviación `—` (`domain.CalcularDesviacion` devuelve `nil`) (D15).
- **Sprint sin historias asignadas:** lista vacía y totales `0`; SP planificados, completados y velocidad en `0` (sin error); "No hay historias asignadas" (R7, R15).
- **Sprint sin defectos:** conteos en cero y listas vacías; "No hay defectos" (R9, R15).
- **Sprint cerrado sin snapshot de esfuerzo:** horas en "métricas no disponibles", desviación `—`, HTTP 200; el resto del reporte normal (D16, R22).
- **Sprint cerrado con estimaciones incompletas:** desviación `—`; horas estimadas suman las disponibles; el resto normal (R8).
- **Sprint cerrado con `SPPlanificados` sin valor guardado (dato inconsistente de US-09/US-16):** `StoryPointsPlanificados` devuelve un error no de dominio; se propaga envuelto → HTTP 500 genérico (E2).
- **Sprint activo (no cerrado):** el reporte se puede generar igual: las horas del Sprint se calculan en vivo (`MetricasSprint` para Sprints activos) y los SP planificados en vivo; el estado del Sprint es "Activo".
- **Sprint inexistente:** HTTP 404 con el mensaje del dominio (R6, R13).
- **Número de Sprint inválido (`"abc"`, `"-1"`, `"0"`):** HTTP 404 sin llamar al servicio (R14, V3).
- **Proyecto inexistente:** HTTP 404 con el mensaje del dominio, en el servicio (R1) y en la web (R13).
- **Error de infraestructura en cualquier llamada:** HTTP 500 genérico; el detalle va al log y no aparece en la respuesta; la plantilla renderiza en memoria antes de escribir, así que no se emiten respuestas parciales (R13).
- **Historias sin estimar en Story Points:** se muestran con `0` SP y nota "sin estimar" si corresponde; no son un error.
- **Defectos resueltos sin Sprint de resolución:** no cuentan como resueltos en ningún Sprint; cuentan por estado (`Resuelto`) a nivel proyecto (R5, R9).
- **Fechas del Sprint iguales:** válidas (el dominio solo rechaza fin anterior a inicio); se muestran como están.
- **Error de fechas del proyecto al calcular el estado (estado por fechas con error):** HTTP 500 con el mensaje genérico; el detalle va al log (V5).
- **Ruta inexistente o método no permitido:** HTTP 404 / HTTP 405 (R20).

// HistoriaReporte es una historia del backlog o asignada a un Sprint, lista
// para presentarse en el reporte. HorasEstimadas es nil cuando la historia
// no está estimada en horas ("sin estimar"). HorasReales es la suma
// histórica de esfuerzo de la historia en todo el proyecto (US-17, D13); en

type HistoriaReporte struct {
	ID             string
	Titulo         string
	Estado         string
	StoryPoints    int
	HorasEstimadas *float64
	HorasReales    float64

// ResumenDefectos combina dos fuentes (D6, D14): Detectados y Resueltos son
// reutilizados tal cual de US-18 (MetricasDefectosPorProyecto en el reporte del
// proyecto; MetricasDefectosPorSprint en el del Sprint); Alta..Resuelto son los
// conteos por severidad y por estado armados localmente iterando la lista
// devuelta por ServicioDefectos.ListarDefectos (US-18 no los expone).
// En el reporte de Sprint, Alta..Total y Defectos contabilizan los defectos
// detectados en el Sprint; DefectosResueltos la lista de resueltos en él.

	Alta     int
	Media    int
	Baja     int
	Abierto  int
	EnCurso  int
	Resuelto int
	Total    int
	// Solo se completan en el reporte de Sprint (D14):
	Detectados        int
	Resueltos         int
	Defectos          []domain.Defecto // proyecto: todos; sprint: detectados en el Sprint
	DefectosResueltos []domain.Defecto // solo sprint: resueltos en el Sprint

// ReporteProyecto es el "modelo de lectura" del reporte del proyecto.
// Los totales se copian de ObtenerDashboard (D2, R2).
type ReporteProyecto struct {
	// Totales del dashboard (reutilizados, no recalculados):
	SPPlanificadosTotal            int
	SPCompletadosTotal             int
	VelocidadPromedio              float64
	PorcentajeHistoriasCompletadas float64
	HorasEstimadasTotal            float64
	HorasRealesTotal               float64
	EstimacionesCompletas          bool

Flujo de `ReporteProyecto`:

1. `s.proyectos.Existe(proyectoID)` (R1). Si no existe, `domain.ErrProyectoNoEncontrado`.
2. `dash, err := s.dashboard.ObtenerDashboard(proyectoID)`; ante error, propagarlo tal como viene (ya viene envuelto o es `ErrProyectoNoEncontrado`).
3. `historias, err := s.backlog.ListarBacklog(proyectoID)` (verifica el proyecto otra vez; inofensivo); ante error, propagarlo. Repartir por estado en `HistoriasCompletadas` (estado `Completada`) y `HistoriasPlanificadas` (el resto), con SP, estimaciones y horas reales (paso 4) tal como vienen.
4. Por cada historia: `m, err := s.esfuerzo.MetricasHistoria(proyectoID, h.ID)` para `HorasReales`; ante error, propagarlo envuelto. *Nota de costo: una llamada por historia; se acepta para no agregar métodos (R10).*
5. `metricasDefectos, err := s.defectos.MetricasDefectosPorProyecto(proyectoID)` (reutilizada de US-18, D6); ante error, propagarlo envuelto con `%w`. `defectos, err := s.defectos.ListarDefectos(proyectoID)`; ante error, propagarlo. Contar por severidad y por estado iterando la lista; armar `Defectos` (`Detectados`/`Resueltos` = `metricasDefectos.Detectados`/`Resueltos`, reutilizados sin recontar; `Total` = `metricasDefectos.Detectados`; `Defectos` = lista completa; `DefectosResueltos` queda vacío/nil en el reporte del proyecto). No se recuenta Detectados/Resueltos desde la lista (D6, R5).

Flujo de `ReporteSprint`:

1. `s.proyectos.Existe(proyectoID)` (R1). Si no existe, `domain.ErrProyectoNoEncontrado`.
2. `sprints, err := s.sprints.ListarSprints(proyectoID)`; ante error, propagarlo. Buscar `Numero == sprintNumero`; si no aparece, `domain.ErrSprintNoEncontrado` sin envolver (R6, V2).
3. `asignadas, err := s.sprints.ListarItemsDelSprint(proyectoID, sprintNumero)`; ante error, propagarlo. Por cada historia: `m, err := s.esfuerzo.MetricasHistoria(proyectoID, h.ID)` para `HorasReales`; armar `HistoriaReporte` (SP, estado y estimaciones desde el ítem; D13).
4. `plan, err := s.sprints.StoryPointsPlanificados(proyectoID, sprintNumero)`; `compl, err := s.sprints.StoryPointsCompletados(proyectoID, sprintNumero)`; `vel, err := s.sprints.VelocidadSprint(proyectoID, sprintNumero)`; ante error, propagarlo (un Sprint cerrado sin `SPPlanificados` guardado produce un error no de dominio que se propaga envuelto → HTTP 500, E2).
5. `m, err := s.esfuerzo.MetricasSprint(proyectoID, sprintNumero)`; si `errors.Is(err, domain.ErrMetricasSprintNoDisponibles)` → `MetricasDisponibles = false`, horas en cero, desviación `nil`, **sin propagar** (D16, R8). Otro error → propagarlo. Si no hay error → copiar `HorasEstimadas`, `HorasReales`, `EstimacionesCompletas`, `MetricasDisponibles = true` y `DesviacionHoras = desviacionSprint(m)` (helper existente de US-19/US-17 con la misma política de nil; R8).
6. `metricasDefectos, err := s.defectos.MetricasDefectosPorSprint(proyectoID, sprintNumero)` (reutilizada de US-18, D6); ante error, propagarlo envuelto con `%w`. `defectos, err := s.defectos.ListarDefectos(proyectoID)`; ante error, propagarlo. Repartir en detectados (`SprintDeteccion == sprintNumero`) y resueltos (`SprintResolucion != nil && *SprintResolucion == sprintNumero`) para las **listas** y los conteos **por severidad/estado** (de los detectados en el Sprint); los conteos globales `Detectados`/`Resueltos` del `ResumenDefectos` provienen de `metricasDefectos` sin recontar. `Alta..Total` contabilizan los detectados en el Sprint (D6, R9).

### 16.3 Conflictos o aclaraciones sobre las decisiones

1. **Estado del proyecto en la capa web vs "las cifras las arma el servicio" (D4 vs D11).** El estado no es una cifra del reporte en el sentido de US-16/US-17/US-19; US-19 D14 y US-22 D11 ya lo calculan en la web con la función pura `EstadoPorFechas`. Hacerlo igual evita pasar el reloj al servicio. El estado sale de esa función y no se reimplementa.
2. **Totales del encabezado (por Sprint) vs suma del backlog (D12).** Son deliberadamente distintos y ambos se muestran con su fuente implícita (el encabezado replica el dashboard; la sección de historias lista el backlog). Consistente con US-19 D10.
3. **Defectos detectados/resueltos en el Sprint (D14) vs US-18 (D6).** El enunciado preveía no usar US-18; al leer el servicio real se verificó que US-18 **sí** entrega `Detectados`/`Resueltos` por Sprint y totales de proyecto vía consultas agregadas (`count(*) FILTER...`) en el adaptador, así que el reporte los **reutiliza** en lugar de recontarlos (decisión confirmada por la persona en la revisión del 2026-11-15). Lo que US-18 **no** entrega — conteos por severidad y por estado y cualquier lista — se arma desde `ListarDefectos` sin agregar métodos (R5, R9). Nota de semántica US-18 que la página no resuelve: `Resueltos` de `MetricasDefectosPorSprint` cuenta solo defectos con estado `Resuelto` y `SprintResolucion == numero`; un defecto reabierto o sin Sprint de resolución no suma ahí (diseño de US-18).
4. **Horas reales por historia históricas, no por Sprint (D13).** US-17 no expone horas reales por historia acotadas a un Sprint; acotarlas requeriría métodos nuevos (fuera de alcance). Se muestra la suma histórica de la historia, igual que la ve `MetricasHistoria`; se informa con una leyenda en la página.
5. **Número de Sprint inválido → 404 (D5/D18), no 422.** Decisión explícita del Product Owner; la web decide sin llamar al servicio (V3).
6. **Un solo PR y un solo ciclo TDD (D8, confirmada 2026-11-15) vs consistencia con US-19 (PRs separados).** US-19 tenía 8 SP y gráficos SVG; US-20 tiene 5 SP y es tabular. La persona confirmó un solo PR con un único ciclo RED/GREEN/REFACTOR y GREEN por tandas internas (servicio, luego web y composición); el beneficio (una sola revisión antes de `develop`) supera al riesgo de mezclar ambas capas, mitigado por los tests estructurales existentes y los dobles de handler.

## 17. Riesgo residual

- **Costo O(n) en llamadas al servicio.** `ReporteProyecto` hace una llamada por historia (`MetricasHistoria`) y `ReporteSprint` una por historia asignada. Para el tamaño típico de un proyecto es despreciable; si importara, sería un método de agregación por proyecto/Sprint (cambio de contrato, fuera de esta historia).
- **Lectura de `ListarSprints` para ubicar el Sprint (D17).** El reporte carga todos los Sprints del proyecto para encontrar el número; aceptado (mismo patrón que `VelocidadPromedio`).
- **Doble verificación del proyecto** en `ListarSprints`/`ListarItemsDelSprint`/`ListarBacklog`/`ListarDefectos` y en `ReporteProyecto`/`ReporteSprint` (sección 16.3).
- **Horas reales históricas por historia (D13).** La suma no está acotada al Sprint; puede mostrar más horas que las del Sprint si la historia tuvo registros en otros Sprints. La página lo aclara con la nota del encabezado `Horas reales (acumuladas)`; el total del Sprint sí sale de `MetricasSprint`.
- **Sin snapshot (Sprint cerrado antes de US-17).** El reporte del Sprint responde 200 con "métricas no disponibles"; la única corrección real sería el snapshot retroactivo, que US-17 descartó explícitamente.
- **Un solo PR, un solo ciclo TDD (D8, confirmada).** Si GREEN detecta en la tanda web un defecto visual, se corrige dentro del mismo ciclo; no hay riesgo de fuga a `develop` sin revisión ni necesidad de evidencias dobles.
- **Doble fuente de defectos (D6, R5, R9).** Si US-18 diverge de `ListarDefectos` (p. ej. un defecto Resuelto sin Sprint de resolución o reabierto), `Resueltos` mostrará menos que el estado del listado; es el diseño de US-18 y se acepta. Severidad/estado y listas siempre salen de `ListarDefectos`, así que un error de consistencia aparecería solo en esos conteos globales.
