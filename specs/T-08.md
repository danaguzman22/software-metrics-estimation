## 1. Objetivo

Definir una suite de contrato compartida en `internal/service/repotest` que verifique la semántica observable de los contratos `RepositorioProyectos`, `RepositorioIntegrantes` y `RepositorioBacklog` definidos por el consumidor en `internal/service`.

La suite debe poder ejecutarse contra `jsonrepo` en T-08 y reutilizarse contra `postgres` en T-13 sin cambios de semántica ni dependencia de tipos concretos de `jsonrepo`, `storage.JSONStore` ni PostgreSQL.

## 2. API del entorno de tests y ejecución real de la suite

`internal/service/repotest` es un paquete normal de Go (no descubre tests automáticamente). La suite debe exportar `Ejecutar` y recibir `*testing.T`. Cada adaptador debe tener su propio archivo `*_test.go` que invoque `repotest.Ejecutar`, por ejemplo:
- `TestJSONRepo_Contrato` en `internal/storage/jsonrepo` (ejecución actual, T-08);
- posteriormente el equivalente en `internal/storage/postgres` para T-13.

La API explícita del entorno de tests es:

```go
type Entorno struct {
	Proyectos       service.RepositorioProyectos
	Integrantes     service.RepositorioIntegrantes
	Backlog         service.RepositorioBacklog
	SembrarProyecto func(t *testing.T, p service.ProyectoRegistrado)
	InyectarFallo   func(t *testing.T) (causa error, ejecutar func() error)
}

func Ejecutar(t *testing.T, nuevo func(t *testing.T) Entorno)
```

Aclaraciones obligatorias:
- **SembrarProyecto:** `RepositorioProyectos` no tiene operación de creación. Todo caso que use integrantes o backlog debe llamar antes a `SembrarProyecto`, porque la ejecución contra PostgreSQL depende de FK hacia proyectos. Los proyectos sembrados deben construirse con `domain.NuevoProyecto` (completando el registro `service.ProyectoRegistrado` con el `ID` y el `Proyecto` resultantes) para respetar las validaciones/invariantes del dominio.
- **InyectarFallo:** es opcional; si es `nil`, el caso/subtest correspondiente a errores de infraestructura se omite mediante `t.Skip`. Si no es `nil`, configura el doble de persistencia, devuelve la causa esperada y devuelve una operación concreta que la suite debe ejecutar; así la suite no adivina qué repositorio ni qué método debe fallar.
- **Aislamiento:** `nuevo` debe devolver un entorno con almacenamiento aislado/limpio para cada ejecución de test.
- **Sin dependencias concretas:** la API y la suite dependen solo de `internal/service`, `internal/domain` y utilidades estándar de test/comparación; no importan `internal/storage/jsonrepo`, `internal/storage` (JSONStore), `pgx`, `database/sql` ni tipos concretos de adaptador.

## 4. Salidas esperadas

| Salida | Tipo | Contenido esperado |
|---|---|---|
| Resultados de contrato observables | Valores y errores devueltos por los métodos de repositorio | Coinciden con las firmas y la semántica de T-06/ADR-001. |
| Colecciones vacías | `[]service.ProyectoRegistrado`, `[]domain.Integrante`, `[]domain.ItemBacklog` | Ausencia de datos se observa como colección vacía sin error cuando el contrato lo define. La comparación acepta `nil` o slice vacío. |
| Errores de dominio | `domain.ErrProyectoNoEncontrado`, `domain.ErrItemNoEncontrado` | Devueltos sin envolver cuando el contrato los define; verificables con `errors.Is`. |
| Errores de infraestructura | `error` envuelto con `%w` | Preservan la causa original (`errors.Is` verdadero sobre la causa provista), no son la causa pelada y no se mapean a errores de dominio. |
| Ítem persistido con ID asignado | `domain.ItemBacklog` | `AgregarItem` devuelve el ítem con ID `HU-NN` calculado por proyecto (`domain.SiguienteIDItem`) y lo persiste. |
| Evidencia automatizada | Ejecución de `go test` | La suite ejecuta en verde contra `jsonrepo` y es reutilizable contra PostgreSQL en T-13. |

## 6. Restricciones

- **Alcance técnico.** Solo se define/especifica la suite de contrato compartida; no se modifica código productivo, tests existentes ni evidencias en esta tarea de especificación.
- **Sin `.feature`.** No se crea `features/T-08.feature`.
- **Sin dependencias concretas.** La suite no debe depender de tipos concretos de `jsonrepo`, `JSONStore` ni PostgreSQL.
- **Suite reutilizable.** Diseñada para ejecutarse contra `jsonrepo` ahora y contra PostgreSQL en T-13 usando helpers compartidos (`Entorno`/`Ejecutar`).
- **Sin casos fuera de alcance.** No incluir duplicados, tags JSON, mutex ni nombres de archivos.
- **Fidelidad al ADR y specs previas.** No se inventan comportamientos ni se dejan decisiones abiertas resolubles leyendo T-06, T-07 o ADR-001.
- **Trazabilidad acotada.** La tabla de trazabilidad lista únicamente tests/subtests que realmente se escribirán durante RED.
- **Estado.** La spec se mantiene en estado **Propuesta** hasta la revisión humana.
