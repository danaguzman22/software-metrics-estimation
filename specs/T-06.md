## 1. Objetivo

Definir en `internal/service` los tres contratos de repositorio por agregado y el tipo exportado `ProyectoRegistrado`, con las firmas exactas de `ADR-001` D2:

- `RepositorioProyectos` (agregado proyectos).
- `RepositorioIntegrantes` (integrantes por proyecto).
- `RepositorioBacklog` (ítems del Product Backlog por proyecto).
- `ProyectoRegistrado{ID, Proyecto}` con tags json `"id"` y `"proyecto"`.

Los contratos los define el consumidor (`internal/service`), no el almacenamiento. Los adaptadores (`internal/storage/jsonrepo` en T-07 y `internal/storage/postgres` en T-13) importarán `internal/service` para satisfacerlos. El dominio no conoce la persistencia.

T-06 **solo declara interfaces y tipos**: no implementa adaptadores, no migra los servicios y no agrega lógica. Los servicios actuales siguen usando `almacen` y los constructores actuales no cambian; esa migración es T-09.

## 6. Contrato de errores y semántica por método

Esta sección transcribe **solo** lo que dice `ADR-001` (D2, D3, D4, D7 y D10). Lo que el ADR no define se marca con una pregunta abierta `Qn` (sección 7) y no se decide en T-06.

Nota general: el ADR no fija los valores de retorno que acompañan a un error (registro, ítem o slice), ni los textos exactos de los errores envueltos. No se inventan en T-06; quedan en `Q10`.

Notas de `RepositorioProyectos`:

- `Obtener` devuelve el registro `{ID, Proyecto}`; el ID vive en la capa de servicio porque `domain.Proyecto` no tiene campo ID (D2, D11 de US-02).
- `Existe` informa si hay un proyecto con ese ID **sin cargar el agregado** (D2).
- `Listar` no tiene un orden definido por el ADR: D7 solo fija orden para ítems e integrantes (`Q2`). Tampoco se fija si el slice vacío es `nil` o `[]` (`Q4`).
- `Actualizar` no recibe una regla de validación de dominio en el contrato: el ADR ubica las validaciones en el servicio/dominio y prohíbe que los adaptadores dupliquen reglas (D1, D3). El contrato solo persiste el proyecto recibido y traduce la ausencia a `domain.ErrProyectoNoEncontrado` (D2).

### 6.2 `RepositorioIntegrantes`

| Método | Éxito | No encontrado / ausencia | Colección vacía | `storage.ErrCorrupt` (solo adaptador JSON) | Otros errores |
|---|---|---|---|---|---|
| `ListarPorProyecto(proyectoID)` | Devuelve los integrantes del proyecto en orden de inserción (D7). | El ADR no define el comportamiento para un proyecto inexistente (`Q3`). | Devuelve una colección vacía, sin error (D3: `ErrNotFound` se traduce a colección vacía). | Se propaga envuelto con `%w` (D3). | Se propagan envueltos con `%w` (D3). |
| `Agregar(proyectoID, integrante)` | Registra el integrante en el proyecto; devuelve solo `error`; `nil` en éxito (D2). | Violación de unicidad del motor (SQLSTATE 23505): `domain.ErrIntegranteDuplicado` (D2, D3). | Un repositorio vacío equivale a colección vacía (D3): el alta procede sin error de colección. | Se propaga envuelto con `%w` (D3). | Se propagan envueltos con `%w` (D3). Notas de `RepositorioIntegrantes`:

- `ListarPorProyecto` ordena por orden de inserción (D7). El adaptador PostgreSQL usa `integrantes.id` IDENTITY; el JSON conserva el orden del slice (D6, D7).
- `Agregar` **no valida duplicados**: el chequeo autoritativo es del servicio con `ListarPorProyecto` + `domain.EsDuplicado` (D2, D3). El índice único de PostgreSQL es defensa en profundidad y su violación 23505 se traduce a `domain.ErrIntegranteDuplicado` (D3, D6). Ningún adaptador ejecuta `domain.EsDuplicado`.
- En el adaptador JSON no hay índice único ni FK (D6 define esas garantías para PostgreSQL): el contrato no asigna al repositorio la validación de duplicados ni de existencia del proyecto; el chequeo de duplicado y la verificación de existencia son del servicio (D2, D3). El ADR no define el comportamiento del adaptador JSON ante llamadas directas con un proyecto inexistente (`Q5`).
- El ADR no fija si el slice vacío es `nil` o `[]` (`Q4`).

### 6.3 `RepositorioBacklog`

| Método | Éxito | No encontrado / ausencia | Colección vacía | `storage.ErrCorrupt` (solo adaptador JSON) | Otros errores |
|---|---|---|---|---|---|
| `AgregarItem(proyectoID, item)` | Asigna el ID "HU-NN" de forma atómica, siguiente al mayor número del proyecto (D4), y devuelve el ítem persistido con su ID (D2). Con backlog vacío asigna "HU-01" (D4). | El ADR no define el comportamiento para un proyecto inexistente en el adaptador JSON (`Q6`). En PostgreSQL, la FK definida en D6 produciría un error de infraestructura que, según D3, se propaga envuelto. | Un backlog vacío produce "HU-01" mediante `domain.SiguienteIDItem` (D4, T-05). | Se propaga envuelto con `%w` (D3). | Se propagan envueltos con `%w` (D3). |
| `ObtenerItem(proyectoID, itemID)` | Devuelve el ítem identificado por `itemID` dentro del proyecto (D2). | `domain.ErrItemNoEncontrado` si no existe **en ese proyecto** (D2). Un `HU-01` de otro proyecto no es el `HU-01` de este (D2, D10). | `domain.ErrItemNoEncontrado` (D10: repositorio sin datos). | Se propaga envuelto con `%w` (D3). | Se propagan envueltos con `%w` (D3). |
| `ListarPorProyecto(proyectoID)` | Devuelve los ítems del proyecto ordenados por número (`HU-01`, `HU-02`, ..., D7). | El ADR no define el comportamiento para un proyecto inexistente (`Q8`). | Devuelve una colección vacía, sin error (D10: "repositorio sin datos → `ListarPorProyecto` devuelve vacío, sin error"). | Se propaga envuelto con `%w` (D3). | Se propagan envueltos con `%w` (D3). |
| `ActualizarItem(proyectoID, item)` | Reemplaza el ítem identificado por `item.ID` dentro del proyecto (D2). Devuelve solo `error`; `nil` en éxito. | `domain.ErrItemNoEncontrado` si no existe en ese proyecto (D2). | El ítem no existe en la colección vacía: `domain.ErrItemNoEncontrado` (D2+D3). | Se propaga envuelto con `%w` (D3). | Se propagan envueltos con `%w` (D3). |

Notas de `RepositorioBacklog`:

- **Regla de numeración de `AgregarItem`.** El ID se asigna con `domain.SiguienteIDItem` (D4, T-05): "HU-01" si no hay ítems previos o ninguno con patrón válido; si no, el mayor número existente más uno, con formato `"HU-%02d"`, comparación numérica e ignorando IDs mal formados. El contrato recibe el ítem **sin ID** y devuelve el ítem persistido con el ID asignado (D2).
- **Atomicidad.** El contrato fija el resultado (ID siguiente al mayor y devolución del ítem persistido), pero la atomicidad es responsabilidad del adaptador (D4): el JSON aplica `SiguienteIDItem` sobre los IDs de la colección del proyecto y guarda; PostgreSQL ejecuta la asignación dentro de una transacción con `SELECT ... FOR UPDATE` sobre la fila del proyecto (D4, D5). La concurrencia real se verifica en T-13, no en T-06.
- **Alcance por proyecto.** `ObtenerItem` y `ActualizarItem` reciben `proyectoID`: la propia firma hace imposible pedir un ítem "sin proyecto" (D2, D10).
- **ID observable.** En PostgreSQL, la PK es `(proyecto_id, numero)` y el ID `"HU-NN"` se deriva de `numero` con `fmt.Sprintf("HU-%02d", numero)` (D4, D6). En JSON, el ID se persiste dentro de `domain.ItemBacklog.ID` (D4).
- El ADR no define qué hacer si `item.ID` ya viene no vacío en `AgregarItem` (`Q7`), ni si `ActualizarItem` permite cambiar el ID (`Q9`), ni si el slice vacío es `nil` o `[]` (`Q4`).

## 9. Casos límite

- **Repositorio vacío (sin datos):**
  - `Existe(id)` → `false`, sin error (D2).
  - `Obtener(id)` y `Actualizar(id, proyecto)` → `domain.ErrProyectoNoEncontrado` (D2+D3).
  - `Listar()` → colección vacía, sin error (D3).
  - `ListarPorProyecto(proyectoID)` de integrantes → colección vacía, sin error (D3).
  - `AgregarItem` → asigna "HU-01" (D4).
  - `ObtenerItem` → `domain.ErrItemNoEncontrado` (D10).
  - `ListarPorProyecto(proyectoID)` de backlog → colección vacía, sin error (D10).
  - `ActualizarItem` → `domain.ErrItemNoEncontrado` (D2+D3).
- **Ítem de otro proyecto:** `ObtenerItem("p2", "HU-01")` cuando `HU-01` existe solo en `p1` → `domain.ErrItemNoEncontrado` (D2, D10).
- **Duplicado de integrante:** violación de unicidad del motor (23505) → `domain.ErrIntegranteDuplicado` (D3). En JSON no hay 23505; el servicio evita el duplicado con `domain.EsDuplicado` (D2, D3).
- **JSON corrupto:** el adaptador JSON propaga `storage.ErrCorrupt` envuelto con `%w`; no se mapea a `domain.ErrProyectoNoEncontrado` ni a `domain.ErrItemNoEncontrado` (D3). Los 6 tests de corrupción existentes se conservan (D10).
- **IDs de ítem mal formados en la numeración:** `domain.SiguienteIDItem` los ignora y calcula el siguiente sobre los válidos (D4, T-05). Con backlog sin IDs válidos → "HU-01".
- **Más de 99 ítems:** el formato no se trunca: "HU-100", "HU-101" (D4, T-05).
- **Concurrencia de `AgregarItem`:** el contrato exige el resultado (ID siguiente al mayor y devolución del ítem persistido); la atomicidad la resuelve cada adaptador (JSON: `SiguienteIDItem` + guardar; PostgreSQL: transacción con `FOR UPDATE` sobre la fila del proyecto, D4/D5). La prueba real de concurrencia es de T-13.
- **Proyecto inexistente en llamadas directas al repositorio:** comportamiento no definido por el ADR para JSON (`Q5`, `Q6`, `Q8`); no se decide en T-06.

## 14. Contrato Go exacto

Bloque de especificación (no implementación). En la fase GREEN de T-06 se crea un archivo nuevo en `internal/service` (nombre propuesto: `repositorios.go`) con estas declaraciones. No se modifica ningún archivo existente.

```go
package service

import "github.com/danaguzman22/software-metrics-estimation/internal/domain"

// ProyectoRegistrado une el ID persistido del proyecto con su agregado de
// dominio. El ID no forma parte de domain.Proyecto (decisión D11 de US-02):
// vive en la capa de servicio y en los contratos que lo devuelven.
// Conserva los json tags actuales para mantener el formato de archivos.
type ProyectoRegistrado struct {
	ID       string          `json:"id"`
	Proyecto domain.Proyecto `json:"proyecto"`
}

// RepositorioProyectos persiste el agregado de proyectos.
type RepositorioProyectos interface {
	// Obtener devuelve el registro {ID, Proyecto}.
	// domain.ErrProyectoNoEncontrado si el ID no existe.
	Obtener(id string) (ProyectoRegistrado, error)
	// Existe informa si hay un proyecto con ese ID, sin cargar el agregado.
	// Un repositorio vacío (sin datos) es Existe == false, no un error.
	Existe(id string) (bool, error)
	// Listar devuelve todos los registros de proyectos.
	Listar() ([]ProyectoRegistrado, error)
	// Actualizar reemplaza el proyecto con ese ID (el ID nunca cambia).
	// domain.ErrProyectoNoEncontrado si el ID no existe.
	Actualizar(id string, proyecto domain.Proyecto) error
}

// RepositorioIntegrantes persiste los integrantes por proyecto.
type RepositorioIntegrantes interface {
	// ListarPorProyecto devuelve los integrantes del proyecto en orden de
	// inserción (D7).
	ListarPorProyecto(proyectoID string) ([]domain.Integrante, error)
	// Agregar registra el integrante en el proyecto.
	// No valida duplicados: el chequeo es del servicio (ListarPorProyecto +
	// domain.EsDuplicado, D3). Ante una violación de unicidad del motor
	// (SQLSTATE 23505, defensa ante carreras) devuelve
	// domain.ErrIntegranteDuplicado (nombre del integrante dentro del
	// proyecto, sin distinguir mayúsculas).
	Agregar(proyectoID string, integrante domain.Integrante) error
}

// RepositorioBacklog persiste los ítems del Product Backlog por proyecto.
type RepositorioBacklog interface {
	// AgregarItem asigna el ID "HU-NN" de forma atómica (siguiente al mayor
	// número del proyecto, D4) y devuelve el ítem persistido con su ID.
	AgregarItem(proyectoID string, item domain.ItemBacklog) (domain.ItemBacklog, error)
	// ObtenerItem devuelve el ítem identificado por itemID dentro del proyecto.
	// domain.ErrItemNoEncontrado si no existe en ESE proyecto.
	ObtenerItem(proyectoID, itemID string) (domain.ItemBacklog, error)
	// ListarPorProyecto devuelve los ítems del proyecto ordenados por número
	// (HU-01, HU-02, ..., D7).
	ListarPorProyecto(proyectoID string) ([]domain.ItemBacklog, error)
	// ActualizarItem reemplaza el ítem identificado por item.ID dentro del
	// proyecto. domain.ErrItemNoEncontrado si no existe en ese proyecto.
	ActualizarItem(proyectoID string, item domain.ItemBacklog) error
}
```

Notas sobre el bloque:

- Las firmas son las de `ADR-001` D2. Los nombres de parámetros (`proyecto`, `integrante`) son los del ADR; en Go el nombre del parámetro no afecta la satisfacción de la interfaz.
- El bloque no importa `internal/storage`, pgx ni `database/sql`. No referencia `storage.ErrCorrupt`: ese error es del adaptador JSON y se documenta en la semántica (D3), no en el contrato.
- El bloque no define `almacen`, `proyectoRegistrado`, constructores ni adaptadores. Esos elementos existentes quedan intactos hasta T-09.
- El tipo exportado `ProyectoRegistrado` convive con el registro no exportado `proyectoRegistrado` de `internal/service/proyectos.go`; la eliminación del no exportado es T-09.
