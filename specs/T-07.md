# T-07 — Adaptador JSON de repositorios

- **Issue:** #41 (T-07)
- **Tipo:** técnica / infraestructura (sin comportamiento de usuario)
- **Estado:** Propuesta
- **Rama:** `feature/T-07-adaptador-json` → PR a `migracion/postgresql`
- **Decisiones del ADR-001:** D1 (repositorios por agregado), D3 (duplicados los decide el servicio), D4 (numeración), D5 (adaptador JSON), D7 (orden)
- **Depende de:** T-06 (#40, contratos en `internal/service/repositorios.go`)
- **Habilita:** T-08 (#42, suite de contrato), T-09 (#43, servicios sobre repositorios)

## 1. Contexto

T-06 definió tres contratos (`RepositorioProyectos`, `RepositorioIntegrantes`,
`RepositorioBacklog`). T-07 los implementa sobre el `JSONStore` existente para
que los 63+ tests de servicio puedan seguir corriendo contra archivos JSON
(T-09) y para tener una segunda implementación contra la cual ejecutar la suite
de contrato (T-08). PostgreSQL llega en T-13.

No hay `.feature`: es infraestructura, no hay comportamiento de usuario que
describir en Gherkin. La trazabilidad es regla → test Go.

## 2. Alcance

**Incluye:** paquete `internal/storage/jsonrepo` con tres adaptadores y sus
tests.

**No incluye:** cambios en `internal/service` (constructores y servicios siguen
con `almacen`; eso es T-09), cambios en `internal/storage` (`JSONStore` no se
modifica), `internal/web`, `cmd`, CI, migraciones ni la suite semántica
compartida (T-08).

## 3. Datos del código actual (relevados)

| Colección | Tipo de registro actual (no exportado, en `service`) | Tags JSON |
|---|---|---|
| `"proyectos"` | `proyectoRegistrado` | `id`, `proyecto` |
| `"integrantes"` | `integranteRegistrado` | `proyecto_id`, `integrante` |
| `"backlog"` | `itemRegistrado` | `proyecto_id`, `item` |

`storage.JSONStore`: `NewJSONStore(dir)`, `Load(name, v)`, `Save(name, v)`.
`Load` devuelve `storage.ErrNotFound` si no existe el archivo y
`storage.ErrCorrupt` (envuelto con `%w`) si el JSON es inválido.

## 4. Reglas

**R1 — Estructura y dependencias.** El paquete `jsonrepo` define la interfaz
`Almacen { Load(name string, v any) error; Save(name string, v any) error }`
(la satisface `*storage.JSONStore`) y tres tipos: `Proyectos`, `Integrantes` y
`Backlog`, con constructores `NuevoProyectos(a Almacen)`,
`NuevoIntegrantes(a Almacen)` y `NuevoBacklog(a Almacen)`. `jsonrepo` importa
`service` y `domain`; `service` NO importa `jsonrepo` ni `storage`.

**R2 — Cumplen los contratos.** `*Proyectos` implementa
`service.RepositorioProyectos`, `*Integrantes` implementa
`service.RepositorioIntegrantes` y `*Backlog` implementa
`service.RepositorioBacklog` (aserciones de compilación `var _ ... = (*X)(nil)`).

**R3 — Mismo formato en disco.** Cada adaptador define sus propios tipos de
registro con los mismos tags de la sección 3 y usa las mismas colecciones.
Un archivo escrito por el servicio actual se lee sin cambios, y viceversa.

**R4 — Colección ausente.** Si `Load` devuelve `storage.ErrNotFound`, la
colección es vacía: `Listar` → vacío, `Existe` → `false`,
`ListarPorProyecto` → vacío (sin error). `Obtener` sobre colección ausente →
`domain.ErrProyectoNoEncontrado`.

**R5 — Corrupción y errores de almacén se propagan.** Si `Load` devuelve
`storage.ErrCorrupt` (o cualquier error distinto de `ErrNotFound`), el método
devuelve un error envuelto con `%w`: `errors.Is(err, storage.ErrCorrupt)` sigue
siendo verdadero. Si `Save` falla, el error se propaga envuelto con `%w` y no se
devuelve resultado exitoso.

**R6 — Proyectos.** `Obtener` y `Actualizar` devuelven
`domain.ErrProyectoNoEncontrado` si el ID no existe. `Actualizar` reemplaza el
agregado `Proyecto` conservando el ID. `Listar` devuelve los registros
`{ID, Proyecto}` en el orden almacenado. `Existe` no falla por proyectos
ausentes.

**R7 — Integrantes.** `Agregar` añade el integrante al final de la colección,
sin validar duplicados ni la existencia del proyecto (son responsabilidad del
servicio, D3). `ListarPorProyecto` devuelve solo los integrantes de ese
proyecto, en orden de inserción (D7).

**R8 — Backlog.** `AgregarItem` carga la colección, calcula el ID con
`domain.SiguienteIDItem` sobre los IDs de los ítems del MISMO proyecto,
persiste el ítem con ese ID y lo devuelve. La numeración es independiente por
proyecto. `ListarPorProyecto` devuelve los ítems del proyecto ordenados por
número (`domain.NumeroDeItem`), no por texto ni por orden de inserción (D7).
`ObtenerItem` y `ActualizarItem` buscan por `(proyectoID, itemID)`.

**R9 — Atomicidad dentro del proceso.** Cada adaptador protege con un
`sync.Mutex` sus operaciones de lectura-modificación-escritura
(`AgregarItem`, `ActualizarItem`, `Agregar`, `Actualizar`). Varias goroutines
llamando a `AgregarItem` sobre el mismo proyecto reciben IDs distintos y
consecutivos, sin pérdida de ítems.

**R10 — Sin cambios fuera del paquete.** No se modifican `internal/service`,
`internal/storage`, `domain`, `web`, `cmd`, `ci.yml` ni tests existentes.

## 5. Criterios de aceptación

- **CA1:** los tres adaptadores satisfacen los contratos de T-06 (R1, R2).
- **CA2:** leen y escriben el formato JSON actual (R3).
- **CA3:** colección ausente se trata como vacía y `ErrCorrupt` se propaga
  envuelto con `%w` (R4, R5).
- **CA4:** `AgregarItem` numera por proyecto y es atómico con goroutines (R8, R9).
- **CA5:** `go test ./... -count=1` en verde, tests existentes sin cambios (R10).

## 6. Fuera de alcance (diferido)

La suite semántica compartida (errores de no encontrado de ítems, aislamiento
entre proyectos, nil ≈ vacío en slices, comparación de fechas, etc.) es de
**T-08**, que la ejecutará contra este adaptador y luego contra PostgreSQL
(T-13). Aquí solo se prueba lo propio del adaptador JSON.

## 7. Trazabilidad

Los tests viven en `internal/storage/jsonrepo` (paquete interno, para poder usar
dobles de `Almacen`). Los casos con `Almacen` real usan `storage.NewJSONStore`
sobre `t.TempDir()`; los de error usan un doble. Los ítems con slices se
comparan con `reflect.DeepEqual` (nil ≈ vacío se normaliza).

## 9. Preguntas abiertas

Ninguna. Decisiones tomadas: interfaz `Almacen` exportada y mínima; tipos de

los no exportados del servicio; el adaptador no verifica la existencia del
proyecto en integrantes ni backlog (lo hace el servicio, T-09).
