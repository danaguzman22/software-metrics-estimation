# T-17 · Barra de navegación contextual y dashboard compacto

**Estado:** Implementada en el Sprint 4.
**Tipo:** tarea técnica (UX). **Responsable:** Dana.

## 1. Motivo
Fuera de un proyecto, la barra superior mostraba Backlog, Sprints, Dashboard y Defectos, pero esos enlaces solo redirigían a `/proyectos`. Además, "Defectos" apuntaba a un marcador global ("Disponible próximamente") aunque cada proyecto ya tiene su pantalla de defectos. El dashboard ocupaba mucho espacio vertical.

## 2. Alcance
- Barra contextual en `base.html`, alimentada por `navContexto`.
- Dashboard: métricas en tarjetas compactas y gráficos en paneles lado a lado (solo plantilla y CSS).
- Sin cambios de dominio, servicios ni persistencia. Sin JavaScript nuevo.

## 3. Criterios de aceptación
| ID | Criterio |
|---|---|
| CA1 | Fuera de un proyecto (`/`, `/proyectos`, `/proyectos/nuevo`, `/defectos`) la barra muestra solo "Proyectos". |
| CA2 | Dentro de un proyecto la barra muestra Proyectos, Backlog, Sprints, Dashboard, Defectos, Reporte e Integrantes, apuntando a las rutas del proyecto. |
| CA3 | "Defectos" dentro de un proyecto apunta a `/proyectos/{id}/defectos`, nunca a `/defectos`. |
| CA4 | Un proyecto inexistente (404) solo muestra "Proyectos". |
| CA5 | La ruta global `/defectos` sigue respondiendo 200 (compatibilidad). |
| CA6 | El dashboard muestra las métricas como tarjetas y los gráficos en un contenedor propio, conservando las tablas accesibles. |
| CA7 | Los botones "Ver ..." del detalle del proyecto se mantienen (T-14/T-15). |
