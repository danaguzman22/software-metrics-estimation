Esta spec no agrega requisitos fuera de esa fuente. Las decisiones tomadas por la persona en el enunciado de la tarea se transcriben en la sección 4 como **DECIDIDAS** (D1–D7). Los escenarios BDD están en `features/US-21.feature`; la implementación sigue el flujo TDD.

## 1. Objetivo y alcance

Entregar al Product Owner la **descarga** del reporte de un proyecto y del reporte de un Sprint como archivo PDF (CA1, CA2), reutilizando exactamente los mismos datos que muestran las páginas HTML de US-20.

El alcance incluye:

- **Generación de PDF (paquete propio):** un generador en `internal/reportepdf` (DERIVADA D9) que recibe los DTO de lectura de `internal/service` (`service.ReporteProyecto`, `service.ReporteSprint`) y la fecha de generación, y devuelve `[]byte` con el PDF, sin depender de HTTP ni de storage (D6).
- **Capa web (descarga):** dos endpoints `GET /proyectos/{id}/reporte.pdf` y `GET /proyectos/{id}/sprints/{numero}/reporte.pdf` en `internal/web`, enlazados con "Descargar PDF" desde las páginas de reporte HTML existentes de US-20 (`plantillas/reporte.html`, `plantillas/reporte-sprint.html`) **sin quitar ni modificar el comportamiento actual** de esas páginas (D1, R13).
- **Contenido:** el PDF incluye el mismo contenido del reporte HTML de US-20 (CA1 de US-20: historias planificadas y completadas, estimaciones, esfuerzo, métricas y defectos), tomado de `ServicioReportes` tal cual; el PDF **no recalcula ni deriva cifras**, solo maqueta y formatea (D2, R4).
- **Sin datos:** un reporte sin datos genera un PDF válido con los mensajes "No hay historias" y "No hay defectos" donde corresponda (CA2, D5).

Fuera de alcance (explícito):

- Migraciones nuevas, cambios de esquema, métodos nuevos en repositorios o cambios en `ServicioReportes`, `ServicioDashboard`, `ServicioSprints`, `ServicioEsfuerzo`, `ServicioBacklog`, `ServicioDefectos` y en `internal/domain` (D7, R7).
- Recalcular, sumar o redondear métricas en el generador o en la web (D2).
- CGO, acceso a red, navegadores/headless, librerías nativas o binarios externos en tiempo de ejecución (D3).
- Vista previa en el navegador, envío por correo, almacenamiento del PDF, exportación a otros formatos.
- Autenticación, roles, paginación, filtros o personalización del contenido del PDF.
- JavaScript en las páginas de reporte HTML (el enlace "Descargar PDF" es un `<a>` de navegación/descarga).
- Cambios en el contenido o la semántica de las páginas HTML de US-20 (solo se agrega el enlace de descarga).

## 2. Entradas

Las entradas son por **ruta** (`GET`; no hay formularios ni `POST`). No se define una API JSON.

| Entrada | Descripción | Origen del requisito |
|---|---|---|
| `id` (ruta) | ID del proyecto. | CA1, CA2, D1, D4 |
| `numero` (ruta) | Número del Sprint (entero mayor que cero). | CA1, D1, D4 |

La fecha de generación no la ingresa el usuario: la capa web la obtiene de `Dependencias.Ahora()` y la pasa al generador para el encabezado (DERIVADA D11, consistente con el reloj inyectable ya usado en la web).

## 3. Salidas esperadas

| Situación | Salida esperada |
|---|---|
| Descarga válida (proyecto) | Respuesta HTTP 200 con cuerpo PDF del reporte del proyecto, `Content-Type: application/pdf` y `Content-Disposition: attachment; filename="reporte-proyecto-{id}.pdf"` (nombre seguro). |
| Descarga válida (Sprint) | Respuesta HTTP 200 con cuerpo PDF del reporte del Sprint, `Content-Type: application/pdf` y `Content-Disposition: attachment; filename="reporte-sprint-{id}-{numero}.pdf"` (nombre seguro). |
| Reporte sin datos | HTTP 200 con un **PDF válido** (comprobable): comienza con `%PDF-`, termina con `%%EOF`, contiene `xref` y `startxref`, tiene al menos una página y no está vacío; incluye los mensajes "No hay historias" y "No hay defectos" (CA2, D5). |
| Proyecto inexistente | Página de error con el mensaje del dominio y HTTP 404 (D4). |
| Sprint inexistente | Página de error con el mensaje del dominio y HTTP 404 (D4). |
| Número de Sprint inválido en la ruta (no numérico o menor que 1) | Página de error con HTTP 404, sin invocar el servicio (D4, V3). |
| Error al generar el PDF o error de infraestructura | Se registra el detalle en el log del servidor y se muestra un mensaje genérico con HTTP 500; el detalle no aparece en la respuesta (D4). |
| Ruta inexistente | HTTP 404. |
| Método HTTP no permitido en una ruta registrada | HTTP 405; el handler no se ejecuta. |

| ID | Decisión (derivada; estado) | Resolución |
|---|---|---|
| D8 | Librería de PDF y manejo de caracteres fuera de cp1252 | **DERIVADA (propuesta):** usar `github.com/go-pdf/fpdf` (fork mantenido de FPDF), librería de generación directa de PDF en **Go puro, sin CGO**, compatible con el stack actual (`go 1.24`, sin dependencias nativas; coherente con el Dockerfile `CGO_ENABLED=0`). Se agrega como **nueva dependencia** en `go.mod` y `go.sum`, pero **su incorporación se realiza en la fase GREEN** (con `go get` y `go mod tidy`) y **no en RED**; la verificación incluye `docker compose up --build`. Se usan las fuentes estándar core del PDF (`Helvetica`, `Helvetica-Bold`) para no requerir archivos TTF externos ni acceso a red; estas fuentes trabajan en codificación WinAnsi/cp1252, que cubre acentos y la eñe del español (`áéíóúñÁÉÍÓÚÑ`, `¿¡`, etc.). Para caracteres **fuera de cp1252** (p. ej. guion largo `—` U+2014, guion medio `–` U+2013, comillas tipográficas `“ ” ‘ ’`, elipsis `…` u otros símbolos no representables) el generador aplica una **normalización explícita** antes de escribir texto: `—`/`–` → `-`, comillas tipográficas → `"`/`'`, elipsis → `...`, espacios no separables → espacio, y cualquier otro rune no codificable en cp1252 se reemplaza por `?` (o se omite de forma controlada), garantizando que el contenido siga legible y el archivo sea siempre un PDF válido sin incrustar fuentes Unicode. Alternativas consideradas: `jung-kurt/gofpdf` (descontinuado; `go-pdf/fpdf` es su sucesor activo), `gopdf`/`maroto` con TTF embebidas (mayor complejidad y activos extra), renderizado HTML→PDF con motor externo (viola "sin navegador/red"). A confirmar. |
| D9 | Ubicación y firmas del generador | **DERIVADA (propuesta):** paquete nuevo `internal/reportepdf` (no importa `internal/web`, `net/http` ni storage). API mínima: `type Opcion func(*configuracion)` y `func SinCompresion() Opcion` (D6, D10); `func GenerarReporteProyecto(reporte service.ReporteProyecto, nombreProyecto string, fechaGeneracion time.Time, opciones ...Opcion) ([]byte, error)` y `func GenerarReporteSprint(reporte service.ReporteSprint, nombreProyecto string, fechaGeneracion time.Time, opciones ...Opcion) ([]byte, error)`. Se recibe `nombreProyecto string` porque `service.ReporteProyecto`/`service.ReporteSprint` no lo contienen y el encabezado debe mostrar el nombre (como en el HTML, tomado del registro). `fechaGeneracion` la provee la web desde `Dependencias.Ahora()` y el generador solo la formatea (no accede al reloj). El resultado es el PDF en memoria; errores de la librería se devuelven envueltos. A confirmar. |
| D10 | Verificación del texto en tests (desactivar compresión) | **DERIVADA (propuesta):** `SinCompresion()` configura la generación sin compresión de streams (p. ej. `SetCompression(false)` en fpdf) para que las cadenas de contenido queden legibles en los bytes del PDF y los tests puedan verificarlas por búsqueda (`bytes.Contains`). La validez estructural (D5: `%PDF-`, `%%EOF`, `xref`, `startxref`, al menos una página, no vacío) se verifica sobre PDFs generados en modo normal y/o sin compresión; la estructura no depende de la compresión. A confirmar. |
| D11 | Maquetación: márgenes, tablas, encabezado y pie | **DERIVADA (propuesta):** página A4 vertical, márgenes 15 mm. Fuentes estándar: `Helvetica` 10 pt cuerpo, 14 pt título, 11 pt negrita para secciones/subtítulos. **Encabezado:** nombre del proyecto, tipo de reporte ("Reporte del proyecto" / "Reporte del Sprint {N}"), datos identificatorios (estado, objetivo/fechas/estado del Sprint cuando aplica) y **fecha de generación** `AAAA-MM-DD` formateada desde `fechaGeneracion` (reloj `Dependencias.Ahora()` pasado por la web). **Pie:** número de página en todas las páginas (p. ej. "Página X", o "Página X de Y" si la librería lo soporta de forma simple). **Tablas:** bordes simples, fila de encabezado en negrita, texto alineado a la izquierda y números a la derecha cuando sea práctico. La maquetación es presentación: no altera valores ni formato numérico de origen salvo el formateo de salida definido por US-20/D15 (dos decimales, sufijos ` h`/`%`, signo, `—`). A confirmar. |
| D12 | Tablas y textos largos, salto de página | **DERIVADA (propuesta):** celdas con texto largo (títulos, objetivos, descripciones) usan salto de línea dentro del ancho de columna (`MultiCell`/equivalente). Si una fila o bloque no cabe en el espacio restante de la página, se fuerza salto de página automático antes de dibujarlo. Cuando una tabla se parte entre páginas se **repite la fila de encabezado** de la tabla en la página siguiente. El contenido no se trunca; se pagina. A confirmar. |
| D13 | Casos límite de contenido | **DERIVADA (propuesta):** el generador produce un PDF válido y legible ante: nombres/objetivos con acentos y eñes, comillas y caracteres normalizados (guion largo → `-`); títulos de historia y descripciones de defectos largos (salto de línea/página); muchos defectos/historias (múltiples páginas). Valores nulos o ausentes se representan como en US-20: horas estimadas no disponibles → `—` ("sin estimar"), desviación no disponible → `—`, listas vacías → los mensajes "No hay historias", "No hay historias asignadas", "No hay defectos" según la sección, y Sprint cerrado sin snapshot → "métricas no disponibles". A confirmar. |
| D14 | Nombres de archivo seguros y enlace en HTML | **DERIVADA (propuesta):** `Content-Disposition` usa `attachment; filename="reporte-proyecto-{id}.pdf"` y `attachment; filename="reporte-sprint-{id}-{numero}.pdf"`. El valor de `{id}` insertado en el nombre se **sanitiza** permitiendo solo `[A-Za-z0-9._-]` y reemplazando cualquier otro carácter por `_` (previene inyección de cabeceras/CRLF y caracteres de ruta); `{numero}` es un entero ya validado. En `plantillas/reporte.html` y `plantillas/reporte-sprint.html` se agrega un enlace `<a class="boton-imprimir" href="/proyectos/{id}/reporte.pdf">Descargar PDF</a>` (y el equivalente con `{numero}` en el reporte de Sprint) **junto al botón Imprimir existente**, sin quitarlo ni alterar el contenido. Las reglas de `@media print` que ocultan el enlace "Descargar PDF" deben estar **acotadas a `.reporte`** (sin reglas globales para `body`, `.navegacion`, etc.), como en US-20. A confirmar. |
| D15 | Integración web y composición | **DERIVADA (propuesta):** los handlers PDF en `internal/web` (p. ej. `reporte_pdf.go`) siguen el patrón de `reporteProyecto`/`reporteSprint`: validan `{numero}` antes de invocar el servicio, obtienen el proyecto con `deps.Proyectos.ObtenerProyecto` (para nombre y errores 404 coherentes) y los datos con `deps.Reportes.ReporteProyecto`/`ReporteSprint`, y delegan la generación a `reportepdf` pasando `deps.Ahora()`. La web y el generador no recalculan ni derivan cifras (D2). `ServicioReportesWeb` **no cambia**. Se registran las rutas `GET /proyectos/{id}/reporte.pdf` y `GET /proyectos/{id}/sprints/{numero}/reporte.pdf` en `aplicacion.go`. `cmd/server/main.go` **no recibe cambios de producción** (ya cablea `ServicioReportes`); la composición y el registro de rutas se verifican con `TestUS21_ConstruirServidorConRutasDePDF` en `cmd/server` (solo test, sin cambios de producción), siguiendo `TestUS20_Fase2_ConstruirServidorConRutasDeReporte` (lección de revisiones). A confirmar. |

## 6. Restricciones

- No se crea ni se edita ninguna migración; no se agregan métodos a ningún repositorio; `internal/service`, `internal/domain` y los adaptadores no se modifican (D7, R10).
- El PDF se genera con librería Go pura, sin CGO, sin red ni navegador en tiempo de ejecución (D3).
- El generador no depende de `net/http`, `internal/web` ni de storage (D6, R9).
- La web y el generador no recalculan ni derivan cifras: solo formatean y maquetan los DTO de `ServicioReportes` (D2, R4).
- `internal/web` no importa `internal/storage` ni `pgx` (regla estructural existente).
- `cmd/server/main.go` no recibe cambios de producción (la composición ya cablea `ServicioReportes`); se agrega en `cmd/server` el test `TestUS21_ConstruirServidorConRutasDePDF` (solo test), siguiendo `TestUS20_Fase2_ConstruirServidorConRutasDeReporte`. El registro de rutas vive en `internal/web/aplicacion.go` (D15).
- Un solo PR y un solo ciclo RED/GREEN/REFACTOR, con GREEN por tandas internas (D7).
- Los textos visibles, mensajes y comentarios en español; archivos en UTF-8 sin BOM (AGENTS.md).
- Sin `template.HTML`; los textos dinámicos de las plantillas HTML siguen escapados por `html/template`.

## 7. Casos límite

- **Proyecto sin historias, sin Sprints cerrados y sin defectos:** PDF válido con "No hay historias" (en planificadas y completadas) y "No hay defectos"; totales en cero/`—` según el DTO del servicio (CA2, D5).
- **Sprint sin historias asignadas y sin defectos:** PDF válido con "No hay historias asignadas" y "No hay defectos"; SP/velocidad en cero (CA2).
- **Sprint cerrado sin snapshot de esfuerzo:** bloque de horas muestra "métricas no disponibles"; el resto del PDF se genera con normalidad (consistente con US-20 D16, R22).
- **Nombres/títulos/objetivos/descripciones con acentos, eñes y comillas:** se renderizan correctamente con fuentes core cp1252.
- **Caracteres fuera de cp1252 (guion largo `—`, guion medio, comillas tipográficas, elipsis):** se normalizan a equivalentes seguros (`-`, `"`, `'`, `...`) sin corromper el PDF (D8).
- **Títulos de historia o descripciones de defectos muy largos:** se muestran con salto de línea dentro de la celda/tabla, sin cortar el contenido (D12).
- **Muchos defectos o muchas historias:** la tabla se parte en varias páginas repitiendo encabezados; el PDF sigue siendo válido y con numeración de página (D11, D12).
- **Horas estimadas `nil` ("sin estimar") y desviación `nil`:** se formatean como `—`, igual que en el HTML.
- **ID de proyecto con caracteres no seguros para nombre de archivo:** se sanitiza en el `filename` del `Content-Disposition` (D14).
- **Número de Sprint `"abc"`, `"0"`, `"-1"`:** HTTP 404 sin invocar el servicio (V3).
- **Proyecto o Sprint inexistente:** HTTP 404 con mensaje del dominio.
- **Error al generar el PDF:** HTTP 500 genérico, detalle solo en log.
